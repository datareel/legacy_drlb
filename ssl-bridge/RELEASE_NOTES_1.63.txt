DRLB SSL bridge 1.63 release notes
11/18/2026 (not yet released)

1.63 is a patch release of the legacy DRLB SSL bridge (drlb_ssl_server)
package: OpenSSL 3.5 on RHEL 8 and post-quantum TLS.

OpenSSL 3.5 on RHEL 8
---------------------
* The 1.62 RHEL 8 RPM (drlb_ssl_server-1.62-1.el8) was built on the RHEL 8
  OpenSSL 1.1.1k (it links libssl.so.1.1). DataReel only ships builds on
  OpenSSL 3.5 LTS or later, so 1.63 replaces it. The RHEL 9 and RHEL 10
  1.62 RPMs were already on OpenSSL 3.5.
* The build stops on OpenSSL headers older than 3.5
  (ssl_bridge/ssl_utils.cpp), the server stops at start if the OpenSSL
  library is older than 3.5, the RPM requires
  libssl.so.3(OPENSSL_3.5.0) and libcrypto.so.3(OPENSSL_3.5.0), and
  rpm_builder/make_ssl_rpm_package.sh refuses older headers, a binary
  that links libssl.so.1.x, or an RPM without the OpenSSL 3.5 requires.
* New build option OPENSSL_PREFIX=/path (env/linux.env) for an OpenSSL
  3.5 install that is not the system one (-I, -L and a matching rpath).
* RHEL 8 hosts need RHEL 8.10 with the updates that bring OpenSSL 3.5.

Post-quantum TLS
----------------
* Key exchange groups are set by the bridge, with the hybrid ML-KEM
  groups (FIPS 203) first: X25519MLKEM768, SecP256r1MLKEM768,
  SecP384r1MLKEM1024, then X25519, secp256r1, X448, secp384r1,
  secp521r1, ffdhe2048, ffdhe3072, on the frontend and on TLS backends.
  The RHEL 8 and RHEL 9 crypto policies do not offer ML-KEM, so 1.62 on
  those releases used classical X25519 only. Classical clients and
  backends still connect.
* ML-DSA (FIPS 204) certificates work on the frontend and on backends:
  the default signature algorithm list adds mldsa65, mldsa87 and
  mldsa44 to the ECDSA, EdDSA and RSA algorithms of the RHEL DEFAULT
  policy. The log shows the certificate key type at start.
* New [SSLCONFIG] settings ssl_groups and ssl_sigalgs. Empty (default)
  uses the lists above, "system" keeps the crypto policy lists, and in
  FIPS mode both default to "system". A bad value is a config error.
* ssl_protocol = TLSv1_2 logs a warning (no post-quantum key exchange
  in TLS 1.2).
* log_level = 4 logs the TLS version, cipher and group of every
  frontend and backend connection.
* The bundled DataReel 6.4.1 files are unchanged.
* New tests/pqc_tests.py (25 checks).

DRLB SSL bridge 1.62 release notes
Released 11/17/2026

1.62 is a patch release of the legacy DRLB SSL bridge (drlb_ssl_server) package.

Changes since 1.61
-----------------------
* Built with the DataReel 6.4.1 library (DataReel 6.4 plus the 6.4.1
  fixes). Only the DataReel files the server uses are included; each
  is the unmodified DataReel 6.4.1 file.
* The local OpenSSL changes once kept in gxssl.h and gxssl.cpp are now
  part of DataReel 6.4 itself: TLS 1.2 minimum, gxSSL_TLSv1_3, no SNI
  for IP addresses, host name checks in the handshake, the system
  trust store, and the handshake timeout keeping a shorter caller
  timeout. SSLv3, TLS 1.0 and TLS 1.1 are refused.
* Sockets are close-on-exec (FD_CLOEXEC): the DataReel 6.4.1 sockets
  and the client sockets the server accepts itself.
* DataReel 6.4.1 thread fixes: a thread is RUNNING as soon as it is
  created, timed waits use the monotonic clock (a system time change
  no longer shortens or stretches them), and the sleep calls no longer
  leak a locked mutex on every call.

DRLB SSL bridge 1.61 release notes
Released 10/31/2026

This is the final release of the legacy DRLB SSL bridge
(drlb_ssl_server) package. drlb_server 2.0 (the tcp_load_balancer
repository) replaces this package: a drlb_server config with an
[SSLCONFIG] section runs as the SSL bridge.

Changes since 1.60 beta
-----------------------
* Version 1.61, a final release instead of a beta. No code changes
  other than the version number.

DRLB SSL Bridge 1.60 beta release notes
Released 10/26/2026 as a beta

This is a beta release. Test it before production use.

Platforms
---------
* RHEL 9 and RHEL 10 (and rebuilds). RHEL 8 only with NetworkManager and
  firewalld running. RHEL 6 and RHEL 7 are no longer supported.
* Native systemd units replace the System V init scripts. The servers
  run as the drlb system user with systemd sandboxing.
* Built with the DataReel 6.2 library. Only the DataReel files the
  server uses are included.

Security
--------
Fixes from the October 2026 security review, including: a heap overflow
in the log queues, a connection flood that stopped the server, a signal
handler that could deadlock or crash on shutdown, unbounded memory per
connection, a busy loop on idle connections, missing timeouts, spoofable
X-Forwarded-For headers, and reverse DNS names trusted without a forward
check.

Behavior changes (no backward compatibility settings)
-----------------------------------------------------
* New settings: write_timeout_secs, connect_timeout_secs,
  max_cache_size and dead_node_secs. use_timeout = 1 by default.
* max_idle_count, idle_wait_secs, idle_wait_usecs and
  use_nonblock_sockets are removed. Default buffer_size is 65536.
* Client X-Forwarded-For headers are replaced, not passed through.
* SO_REUSEPORT is no longer set on the listening socket.
* Round robin skips a node that refused a connection for
  dead_node_secs and spreads its share over the live nodes.

Testing
-------
python3 tests/ssl_bridge_tests.py runs the regression tests.

TLS and OpenSSL 3.5
-------------------
* OpenSSL 3.5 API (RHEL 9 and 10); still builds with OpenSSL 1.1.1 on
  RHEL 8.
* ssl_protocol accepts TLS (TLS 1.2 and 1.3, default), TLSv1_2 and
  TLSv1_3. SSLv23 and older protocols are a configuration error.
* Ciphers follow the system crypto policy; ssl_cipher_list and
  ssl_ciphersuites can restrict them. The per connection "ALL" cipher
  list is gone.
* Back end certificates are verified by default (subjectAltName, SNI).
* ssl_handshake_timeout_secs bounds the TLS handshake. Connections now
  end with a TLS close_notify.
